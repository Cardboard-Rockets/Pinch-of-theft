# PopTheLock — Unity 6000.6

Откройте `Scenes/PopTheLock.unity` и нажмите Play. Сервер, замки, ключ, камера и интерфейс создаются при запуске из назначенных локальных ресурсов. До Play в сцене виден корневой объект PopTheLock с настройками.

## Правила

- В центре расположен сервер; вокруг него восемь закрытых замков. Ключ вращается по внешнему кругу и направлен зубцами к центру.
- ЛКМ или пробел запускает попытку. Нужно нажать, когда ключ находится напротив любого закрытого замка, в пределах допустимой угловой погрешности.
- Каждая принятая попытка меняет направление вращения на противоположное, независимо от попадания. При промахе разворот происходит сразу; при попадании ключ продолжает вращение в обратную сторону после возврата. Нажатия во время анимации игнорируются и направление не меняют.
- При попадании ключ притягивается к замку, открывает его, ненадолго задерживается и возвращается на внешнюю окружность. Затем вращение продолжается.
- Справа сверху показаны жизни в виде ключей; по умолчанию их три. Каждый промах убирает один ключ.
- При промахе ключ немного приближается к центру и возвращается, продолжая вращаться. Открытые замки сохраняются. После последнего промаха завершается его короткая анимация и наступает поражение.
- После поражения отпустите кнопку и нажмите ЛКМ или пробел заново: восстановятся жизни, все замки закроются, ключ вернётся к исходному углу и направлению.
- Замки можно открывать в любом порядке. Попытка у уже открытого замка считается промахом.
- Во время короткой анимации повторные нажатия игнорируются; удержание кнопки не создаёт новые попытки.
- После открытия всех замков ключ завершает возврат и игра останавливается без меню. Счёт остаётся 8 / 8. Приложение-хост не закрывается.

## Настройки в инспекторе

Выберите объект **PopTheLock** до входа в Play Mode.

Компонент **Pop The Lock Game**:

| Параметр | Значение | Назначение |
| --- | --- | --- |
| Lock Count | 8 | Число замков |
| Starting Lives | 3 | Начальное количество жизней, отображаемых ключами справа сверху |
| Angular Speed | 100 | Скорость в градусах в секунду |
| Clockwise | On | Начальное направление по часовой стрелке; после попытки направление меняется |
| Hit Angle | 10 | Допустимое отклонение от замка в каждую сторону, в градусах |
| First Lock Angle | 90 | Первый замок сверху; остальные равномерно по кругу |
| Initial Key Angle | 67,5 | Начальный угол ключа |
| Pull Duration | 0,18 | Время притяжения к замку |
| Hold Duration | 0,12 | Пауза у открытого замка |
| Return Duration | 0,22 | Время возврата наружу |
| Miss Duration | 0,32 | Продолжительность движения при промахе |
| Miss Depth | 0,25 | Доля расстояния между окружностями для приближения при промахе |

При большом числе замков допустимый угол автоматически ограничивается, чтобы зоны соседних замков не перекрывались. Меньшая скорость и больший Hit Angle упрощают игру.

Компонент **Lock View**:

| Параметр | Значение | Назначение |
| --- | --- | --- |
| Center | (0, 0) | Центр сервера и окружностей |
| Lock Radius | 3,4 | Радиус окружности замков |
| Key Radius | 5,4 | Радиус внешней окружности ключа |
| Server Width | 2,4 | Ширина сервера |
| Lock Width | 1,9 | Ширина изображения замка |
| Key Width | 2 | Ширина изображения ключа |

Размеры задаются для полного изображения, включая прозрачные поля. Высота меняется пропорционально ширине. Key Radius должен быть больше Lock Radius; при слишком маленьком значении он автоматически увеличивается. При увеличении числа замков уменьшите Lock Width или увеличьте Lock Radius, чтобы картинки не перекрывались.

| Файл Art | Размер | Использование |
| --- | --- | --- |

| server (1).png | 220×240 | Сервер |

| lockopen (1).png | 240×240 | Открытые замки |
| lockvibrani (1).png | 240×240 | Сохранён, не используется: выбранного целевого замка нет |
| lockprocheknyti (1).png | 240×240 | Сохранён, не используется по согласованию |

Маленькие версии всех изображений сохранены, но не используются. У фона большая версия — без `(1)`. Исходные изображения не менялись, новые рисунки не создавались. Используемые текстуры импортированы как Sprite Single, Point, без mipmaps и компрессии, Max Size 4096.

Масштаб всех спрайтов одинаков по X и Y; пропорции сохраняются. При изменении формата окна камера вписывает фон с полями. Фон не прокручивается.

UI/Arial.ttf — локальная копия системного шрифта с кириллицей. Интерфейс — uGUI Text с явно назначенным шрифтом. Материал и шейдер хранятся в Materials. Игровых ссылок на Runner, Snake и SpaceBoat нет. API Unity/uGUI и UnityCG являются стандартными зависимостями движка.

## Структура

- Scripts/LockRound.cs — независимая от Unity модель углов, попаданий, фаз анимации и победы.
- Scripts/PopTheLockGame.cs — параметры и ввод через Input System.
- Scripts/LockView.cs — сервер, замки, ключ и счёт.
- Scripts/LivesView.cs — иконки ключей-жизней, закреплённые в правом верхнем углу Canvas.
- Scripts/PopTheLockScene.cs — камера, фон, локальные ресурсы и uGUI.
- Scenes/PopTheLock.unity — независимая сцена.
- Editor/LockVerification.cs — проверки правил, изоляции и запуска сцены во временном проекте.

Своя сборка PopTheLock, пространство имён PopTheLock. В текущем проекте уже включён Active Input Handling = Input System Package (New). Настройки проекта, физика, слои и теги не менялись. Глобальное время не останавливается. Сцена в Build Profiles автоматически не добавляется.

## Проверки

В редакторе доступны **Tools → PopTheLock → Verify Rules** и **Validate Isolation**. Эти команды не меняют настройки проекта. Подробный результат — в Verification.txt.

- [ ] Восемь закрытых замков расположены вокруг сервера, ключ снаружи.
- [ ] ЛКМ и пробел открывают любой замок при совпадении угла.
- [ ] Ключ притягивается, замок открывается, ключ возвращается.
- [ ] При промахе вращение продолжается, ключ лишь ненадолго приближается.
- [ ] Жизни уменьшаются 3 → 2 → 1 → 0; после последней игра останавливается и предлагает перезапуск.
- [ ] Прогресс не сбрасывается; уже открытый замок не увеличивает счёт повторно.
- [ ] После восьми открытий игра останавливается.
- [ ] Все спрайты сохраняют пропорции и используют максимальное разрешение.
- [ ] Все игровые ресурсы локальны, перед каждым методом C# стоит однострочный русский комментарий.

Автоматическая проверка проходила без графического устройства. Внешний вид и реальные нажатия ЛКМ/пробела требуют ручной проверки в Game View.
